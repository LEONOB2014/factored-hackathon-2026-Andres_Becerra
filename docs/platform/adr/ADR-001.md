# ADR-001 · Lakehouse with lossless bronze, medallion zones and a Kimball core

Status: accepted (2026-10) · revised 2026-10-05 · refined by [ADR-013](ADR-013.md), [ADR-014](ADR-014.md),
[ADR-016](ADR-016.md), [ADR-017](ADR-017.md)

## Context
The bank's data arrives as daily CSV files (13 source tables, 2023-06-17 → 2026-06-17) carrying defects:
- injected nulls in mandatory fields;
- products opened before their customer existed;
- currencies mislabelled;
- a backup folder that is a different dataset ([backup comparison](../../dataset/backup_comparison.md)).

A regulator must be able to ask what arrived, what was changed, by whom and why. Consumers need governed dimensional
data for analysis and denormalised marts for products such as the copilot. Everything must run on a laptop first.

## Decision drivers
- **Evidence over convenience:** nothing that arrived may be lost or silently coerced.
- **Repairs are visible and reversible**, never overwrites.
- **One governed definition per business concept,** reused by every mart.
- **Separate trust levels and data classes** (personal, tokenised, aggregated) per zone.

## Decision
1. **Landing → bronze_raw.** Every landed file is fingerprinted (sha256 against the landing manifest) and stored as
   **lossless bronze**:
   - every field kept as its original text;
   - per-record lineage (`_source_file`, `_source_sha256`, `_record_no`, `_record_sha256`, `_parse_status`);
   - append-only partitions;
   - a per-file proof that the stored artefact rebuilds the source byte for byte.

   Facts after the stream cutoff go to `holdout_raw`; the untrusted backup goes to `quarantine`.
2. **Silver types bronze against reviewed source contracts** (`platform/contracts/sources`), behind a schema-drift
   circuit breaker that holds a partition instead of guessing. Repairs are four-eyes corrections in a write-once
   log overlaid on bronze, never edits of it (chapter 09 §C–§D).
3. **Gold is a Kimball core:** SCD2 dimensions, facts at their natural grain, and use-case marts. On top of it, a
   **multi-grain aggregate layer** (ADR-017) holds day, cell and hour grains, contract-tested.
4. **Purpose zones** after gold: features, graph, knowledge, privacy, serving and audit, each with its own data
   class.
5. **dbt implements silver and everything after it**; Airflow orchestrates (ADR-002).

## Implementation
- `platform/libs/latam_platform/lakehouse/` (`landing.py`, `bronze_raw.py`, `raw_records.py`).
- `platform/dbt/models/{silver,gold,features,graph,knowledge,privacy,serving,audit}` and `gold/aggregates`.
- The DAGs `landing_ingest`, `bronze_build` and `dbt_lakehouse` (scope ALL); `lakehouse_<mx|co|ar>` per country
  (ADR-020).

## Evidence and verification
On the end-to-end run of 2026-10-03 ([platform README](../README.md)):
- 12,505 files fingerprinted; all 13 tables reconcile with **0 rejected and 0 lost**;
- manifests sealed in object-locked MinIO;
- every dbt layer green behind the quality and governance gates.

Two builds of the same commit give identical relations ([reproducibility evidence](../evidence/reproducibility/README.md)).
Corrections applied, reverted and rebuilt "as of" a point in the log reproduce exactly
([phase 4 evidence](../evidence/phase4/README.md)).

## Consequences
- **Positive:**
  - every number traces to a byte-exact source record;
  - defects become flagged findings, not silent coercions;
  - trust and data class are explicit per zone;
  - the same compiled project runs per country (ADR-016).
- **Negative:**
  - more layers to build and test;
  - the lossless copy roughly doubles bronze storage;
  - the laptop build needs memory-bounded profiles (ADR-006).
- **Risks:**
  - zone sprawl. Mitigated by generated lineage (`docs/platform/generated/dbt_lineage.md`), dbt contracts and the
    governance gate.

## Alternatives considered
- **A single wide-table warehouse** (rejected): mixes grains, leaks future information into features, and hides
  repairs. It would win only for a one-off analysis with no regulator.
- **A data vault** (rejected for now): stronger historisation, but heavier modelling than 13 source tables justify.
  Reconsider if the number of source systems grows into the dozens.
- **Typed bronze as the record** (retired): type coercion turns `''` into NULL and loses evidence. It is kept only as
  an archive (`lakehouse/bronze.py`).

## Revisit when
- **Volumes outgrow single-node DuckDB:** move the lakehouse to Iceberg tables with row-level deletes (also the
  production path for erasure, ADR-008).
- **A second source system arrives:** reconsider a vault-style integration layer.

## Revision note
The original text (2026-10) described bronze as "typed, append-only, digests". Typed bronze was retired when silver
started typing the lossless bronze against source contracts. The header of `bronze_raw.py` still says "until silver
reads this zone (phase 3)", which is stale: phase 3 is implemented (chapter 09 §C). The decision to use medallion
zones with a Kimball core is unchanged.
