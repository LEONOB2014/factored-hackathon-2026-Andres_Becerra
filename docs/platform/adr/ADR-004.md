# ADR-004 · Neo4j for GraphRAG and the entity graph

Status: accepted (2026-10) · revised 2026-10-05 · related [ADR-003](ADR-003.md), [ADR-010](ADR-010.md),
[ADR-021](ADR-021.md)

## Context
Two needs share a graph:
1. **Compliance and knowledge questions traverse relations:** regulation → control → model, a document version →
   the version it supersedes, a chunk → the entities it mentions. Pure vector search cannot answer "which controls
   does this regulation touch".
2. **Fraud and AML reasoning needs neighbourhoods:** customer → card → merchant → other customers. Graph learning
   results (ADR-010) need a home that analysts can query.

## Decision drivers
- **Expressive multi-hop traversals,** with a vector index next to the graph.
- **Only governed, active knowledge** is ever reachable.
- **Tokens only:** no direct identifiers in the graph (the PII handling standard).
- **Rebuildable from governed sources** at any time; the graph is never the system of record.

## Decision
1. **The knowledge graph:**
   - `(:Document)-[:HAS_VERSION]->(:DocVersion)-[:HAS_CHUNK]->(:Chunk)-[:MENTIONS]->(:Entity)` plus
     `(:DocVersion)-[:SUPERSEDES]->(:DocVersion)`;
   - chunks carry the same multilingual-e5-small embeddings as pgvector, in the `chunk_embedding` vector index;
   - entities are deterministic (controls, rules, regulators, regulations, dbt models), extracted at sync;
   - versions carry `active`, kept equal to the registry by reconciliation.
2. **The entity graph:** customers, products, merchants, branches and agents as tokenised nodes, loaded from gold by
   `graph_load`. It feeds the temporal and federated graph models.
3. **Both are derived:** `kb_sync` and `graph_load` rebuild them from governed sources. After every sync the active
   set must be identical in the registry, pgvector and Neo4j, or the run fails.
4. **Cloud:** Neo4j Enterprise or AuraDB in region (Community lacks fine-grained RBAC and clustering).

## Implementation
- `platform/libs/latam_platform/kb_pipeline.py` (graph model, `CREATE VECTOR INDEX chunk_embedding`, reconcile).
- `platform/airflow/dags/kb_sync.py` and `platform/airflow/dags/graph_load.py`.
- GraphRAG consumer: `copilot/src/copilot/kb.py` (`GraphRetriever`). It seeds from the vector index and expands one
  hop through shared entities of active versions.

## Evidence and verification
- **Knowledge:** 9 approved versions active and reconciled across registry, pgvector and Neo4j; draft, superseded,
  retired and expired versions never indexed ([platform README](../README.md)).
- **Entity graph:** 14k nodes and 93k edges for the 2 % demo sample.
- **Measured retrieval** ([copilot retrieval report](../../../copilot/eval/reports/kb_retrieval.md), 28 ES/PT
  questions):
  - GraphRAG hit@1 0.69 and hit@3 0.94, against pgvector's 0.75 and 0.94;
  - **zero governance violations** for every retriever;
  - on this small corpus, graph expansion does not beat plain vectors.
- The active-set hash is identical in Neo4j, pgvector and the bundled index (`build_kb_index.py --verify`).

## Consequences
- **Positive:**
  - multi-hop questions and explainable retrieval paths (each chunk records how it was found);
  - one place for graph features and their analysis.
- **Negative:**
  - another store to secure and reconcile;
  - Community edition limits (no RBAC granularity, no clustering) restrict the local setup to a demo.
- **Risks:**
  - drift between graph and registry. Mitigated by reconciliation on every sync and a failing run on mismatch.

## Alternatives considered
- **Graph tables in Postgres** (rejected): recursive SQL works, but traversal ergonomics and graph algorithms are
  poor. It would win if the graph were a few hand-written joins.
- **Spanner Graph on GCP** (deferred): a single managed store for relational and graph data. Evaluate when the cloud
  is applied.
- **Vector-only retrieval** (kept as the baseline): it wins today on this corpus. The graph earns its place when
  documents cross-reference each other heavily.

## Revisit when
- **The knowledge base grows into hundreds of interlinked documents:** re-run the retrieval comparison; keep
  GraphRAG only if it beats vectors.
- **Real counterparty data arrives:** the entity graph becomes a fraud feature source (ADR-010, chapter 07).
