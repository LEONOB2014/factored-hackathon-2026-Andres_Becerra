# ADR-006 · DuckDB for development, BigQuery as the analytics layer

Status: accepted (2026-10)

## Context
Fast local iteration on 4.4 M transactions; cloud analytics must respect residency.

## Decision
dbt-duckdb for dev/CI; dbt targets bq_mx/bq_br build a BigQuery-native analytics layer (authorized views, DP views) over tables published per region; heavy transforms stay in the lakehouse.

## Consequences
Laptop builds in about two minutes; BigQuery receives only tokenised gold/serving/privacy data. Some DuckDB SQL would need dispatch macros if transforms moved fully to BigQuery.

## Alternatives considered
Run all dbt in BigQuery (rejected for now: cost and residency complexity for raw PII).
