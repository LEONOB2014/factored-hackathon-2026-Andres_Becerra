# ADR-005 · Flink for streaming features

Status: accepted (2026-10)

## Context
Real-time fraud scoring needs event-time windows identical to the batch features.

## Decision
Redpanda (Managed Kafka in GCP) + Flink SQL with one OVER frame per view joined per transaction; Python scorer completes history features from batch-warmed state; parity test against dbt on every demo run.

## Consequences
Exactly-once windows with watermarks and a provable stream/batch contract. Higher operational load than a Python-only consumer.

## Alternatives considered
Pure Python stream processor (lighter, but no exactly-once windowing at scale).
