# ADR-002 · Airflow 3 with Astronomer Cosmos for orchestration

Status: accepted (2026-10) · revised 2026-10-05 · related [ADR-018](ADR-018.md), [ADR-020](ADR-020.md)

## Context
The pipelines span:
- ingestion with integrity proofs;
- dbt builds of a dozen layers;
- ML training with approvals;
- streaming control;
- compliance jobs: erasure, differential-privacy releases, audit anchors, regulatory triggers.

Regulators expect evidence for every run: what ran, on which inputs, who approved what. Data corrections need a
human decision by someone other than the proposer. The whole stack must also run on a laptop with about 8 GB for
Docker.

## Decision drivers
- One orchestrator for batch, ML, streaming control and compliance, with **run evidence and lineage**.
- **Native human approval** steps.
- **Per-model visibility** of dbt (a failed model, not a failed "dbt run").
- A **managed option in the target cloud** (GCP) without rewriting the DAGs.

## Decision
1. **Airflow 3.1** (image `latam/airflow:3.1.0`) with the platform code in an isolated venv (`PLATFORM_PY`) and dbt
   in its own venv.
2. **Asset-based scheduling.** DAGs produce and consume named assets (landing, bronze, lakehouse, serving, knowledge,
   graph, fraud model, stream decisions in `latam_dags/common.py`), so a new bronze triggers the lakehouse, and so on.
3. **Astronomer Cosmos** renders dbt as one Airflow task per model, grouped by layer (`DbtTaskGroup`), from the
   compiled manifest, with tests after each group.
4. **Human in the loop with Airflow's HITL operator.** The data-correction review asks an approver for a decision
   and a recorded comment, and refuses an approval by the proposer (four eyes).
5. **OpenLineage** emits lineage to Marquez for every task. Every DAG also writes to the hash-chained audit ledger
   through audit callbacks.
6. **Cloud:** Cloud Composer 3 per residency environment, defined as a Terraform module (not applied).

## Implementation
- **17 DAG files** in `platform/airflow/dags/`; `lakehouse_scoped.py` generates 3 more (`lakehouse_mx`,
  `lakehouse_co`, `lakehouse_ar`).
- Shared layers, assets and callbacks: `platform/airflow/include/latam_dags/common.py`.
- Image: `platform/docker/airflow/` (platform and dbt venvs, `astronomer-cosmos>=1.10`, the OpenLineage provider).
- Terraform: `platform/infra/terraform/gcp/modules/composer`.

## Evidence and verification
- **End-to-end run (2026-10-03):** landing → bronze → 90+ Cosmos dbt tasks → quality and governance gates →
  serving publication. Every step is in the ledger, and `verify_chain` reports 0 problems
  ([platform README](../README.md)).
- **DAG integrity tests:** 19 at the time of the run, which load every DAG and check its structure; a DagBag of the
  scope DAGs loads with 0 import errors.

**Problems the run surfaced and fixed:**
- The LocalExecutor pre-forked 32 workers of about 220 MB each, so `AIRFLOW__CORE__PARALLELISM=4`.
- Cosmos runs dbt from a temporary copy, which broke relative lake paths: the env is inherited (`append_env`) with an
  absolute `LATAM_LAKE_DIR`.
- Cosmos telemetry was disabled (`AIRFLOW__COSMOS__ENABLE_TELEMETRY=False`).

## Consequences
- **Positive:**
  - per-model status and retries;
  - lineage and audit for every run;
  - approvals inside the orchestrator;
  - the same DAG code locally and in Composer.
- **Negative:**
  - each Cosmos model is a separate process, which adds overhead;
  - DuckDB's single writer forces a shared pool that serialises heavy tasks inside the memory-capped scheduler
    (ADR-020).
- **Risks:**
  - Airflow 3 is young (HITL, asset APIs). Mitigated by pinned images and DAG integrity tests.

## Alternatives considered
- **Dagster** (rejected): an excellent asset model, but no managed offering in the target cloud and a weaker
  approval story. It would win for a team with no Composer constraint.
- **dbt Cloud jobs only** (rejected): no control of ML, streaming or compliance jobs.
- **Prefect** (not chosen): lighter, but lineage and human approval would be built by hand.

## Revisit when
- **Cosmos overhead dominates run time:** evaluate Cosmos watcher mode or dbt Fusion.
- **The lakehouse moves off DuckDB:** remove the serialising pool.
- **The cloud is applied:** confirm Composer 3 supports the HITL operator version in use.
