# ADR-003 · Postgres + pgvector as the operational and vector store

Status: accepted (2026-10)

## Context
Serving lookups, online features, decision logs and the knowledge base need transactions, row-level security and audited access; vector volume is small (KB of policies).

## Decision
pg-core holds bank_serving and knowledge (pgvector HNSW); the audit store is a separate Postgres instance on an isolated network.

## Consequences
One technology for operational data and vectors, mature security, Cloud SQL in-region. Vector scale limited to millions of chunks; a dedicated vector DB is an option later.

## Alternatives considered
Dedicated vector database (rejected: another store to secure and audit for little gain at this size).
