# ADR-018 · Model readiness gates and the data-collection audit

Status: accepted (2026-10)

## Context
ADR-012 gates the model portfolio on evidence. The hour series (`eda/notebooks/granularity_hour/08`) went further:
every candidate model was trained out of time whatever the signal, and one rule turned each result into a verdict.
Eleven models: 0 green, 2 amber, 9 red (8 generator independence, 1 data defect). The red gates became requirements
with an owner and an acceptance test (strategy chapter 13). `eda/scripts/readiness_check.py` reproduces the
scorecard byte for byte and re-runs it on any lake.

## Decision
1. **One readiness rule for every model** (`latam_eda.granularity.readiness_verdict`). The out-of-time gain over a
   transparent benchmark is bootstrapped, then:
   - **green**: the 95 % interval excludes 0 and the gain reaches the materiality threshold;
   - **amber**: significant but not material, or the folds disagree;
   - **red**: otherwise, with a root cause:
     - *insufficient volume* when the minimum detectable effect (2.8 bootstrap standard errors) exceeds the
       threshold;
     - else the scenario's diagnosis: generator independence, missing field or data defect.
2. **A red or amber gate is a data requirement, not a dead end.** It names:
   - what the source must collect;
   - who owns it;
   - the acceptance test on a new feed;
   - the threshold that turns it green.
3. **The scorecard runs as a pipeline step per scope** after the aggregates (ADR-020). New data re-judges every gate;
   a green gate opens the model path of ADR-012.
4. **The share of green gates is a data-office KPI,** reported per scope and quarter.

## Consequences
- Non-trainable models are documented results, not abandoned work. The audit is the specification for the
  data-collection process.
- Each model carries its benchmark, materiality threshold and minimum detectable effect from the start. "Not enough
  data" is measured, not argued.
- Today the scorecard runs in the EDA environment. Running it inside Airflow needs the gate functions moved into
  `latam_platform` (next step after ADR-020).

## Alternatives considered
- **Train only where signal is expected** (rejected): the negative results and their root causes are what tell the
  bank which data to collect.
- **A score threshold without intervals** (rejected): on this volume, a tiny significant gain and a material gain
  look alike without the interval and the materiality test.
